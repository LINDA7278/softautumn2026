# Background
GitHub was conceptualized in late 2007 by founders Tom Preston-Werner, Chris Wanstrath, P.J. Hyett, and Scott Chacon, arising from a desire to make the highly powerful but complex command-line tool Git easier to use and more collaborative. Officially launched in April 2008, the platform quickly expanded from a niche tool for the Ruby on Rails community into the dominant central hub for global software development, surpassing traditional hosting platforms like SourceForge by 2011. Recognizing its immense value to the engineering world, tech giant Microsoft acquired GitHub for $7.5 billion in October 2018, allowing it to continue operating independently while introducing powerful enterprise integrations and automation capabilities. Today, GitHub has transcended basic hosting to become a massive global social network for engineers, housing over 800 million repositories and driving modern innovations like the AI-powered coding companion GitHub Copilot.

# Introduction

GitHub is a cloud-based hosting service and collaboration platform designed for software developers to store, manage, and track changes to their code. Built on the foundation of Git—an industry-standard version control system—it allows multiple programmers to work on the same project simultaneously without overwriting each other's contributions. By providing a centralized, user-friendly interface for code review, project management, and automated testing, GitHub has become the world's largest repository host and the central hub for open-source software development.

# Dictionary

GitHub is a cloud-based development platform built on top of Git, a local version control system designed to track changes in code files over time. At its core, projects are organized into repositories (repos), which serve as central digital folders containing all project files and their complete revision history. Developers use branches to create parallel workspace copies where they can test new features safely without disrupting the primary code (main). Once changes are made and saved via a commit, developers submit a pull request (PR) to invite team members to review their work. After approval, the new code is merged back into the main project. Users can also fork someone else's public repository to create an independent copy under their own account, or clone a repo to download a functional version directly to their personal computer for offline editing.
